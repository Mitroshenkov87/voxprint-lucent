# M3 Enlarge hand-off

Lucent's Enlarge client lives in the tools process. The C++ viewer does not talk to Enlarge, and `--benchmark` does not start the tools process. The first-visible-pixel guard on that path stays at 250 ms.

The product Enlarge server is not available yet. CI runs the client against `python -m voxprint_lucent.enlarge_mock`, which speaks protocol 1. The agreed contract is [IPC-ENLARGE.md](IPC-ENLARGE.md). How Lucent finds Enlarge is [APP-DISCOVERY.md](APP-DISCOVERY.md). Lucent keeps its own copy of that lookup in `voxprint_lucent/discovery.py` until a shared `voxprint-common` package is approved.

## What works

- Discovery reads `LUCENT_ENLARGE_EXE` (a test hook), then the Linux desktop file or the Windows `HKCU\Software\Voxprint\Enlarge` key (including `InstallPath`, `Version`, and `IpcName`), then App Paths, then `voxprint-enlarge` on `PATH`. The executable has to exist. Flatpak is not probed.
- `--capabilities --json` is cached for a day and refreshed when the registered `Version` changes. `gpu.status` `ok` enables the actions. `warn` leaves them enabled. The mock's warn `reason` is null, so the tooltip is `warn`; a reason that is present is shown instead. `none` leaves them disabled and shows `no_nvidia` or `driver_too_old`, with no install button. The probe itself still exits 0 when there is no GPU. `--serve` refuses in that case. The mock's `--serve` remains for Enlarge's own server; Lucent does not call it.
- Quick enlarge and Open in Enlarge run the headless `voxprint-enlarge` CLI with `--json-progress`. Quick enlarge passes `--scale 2`. Open in Enlarge omits the scale, so Enlarge uses 4. Neither flag opens a window. Lucent does not open the socket. If Enlarge is not installed, the action is disabled and Install Enlarge opens the Enlarge releases page.
- Progress, `done`, and `error` (including retryable `model_missing`) are read from the CLI's stdout. Cancel terminates that process. `io_error` and `internal` are not retryable. `--dry-run` checks the GPU and does not write the file. A missing GPU exits 4.
- The default result is `<name>.enlarged-<scale>x.<ext>` beside the source. JPEG uses `.jpg`. A collision starts at `-2` (`shot.enlarged-2x-2.avif`, or `out-2.avif` for an explicit path). PNG is rejected. The source is never overwritten.
- The compare view is a split slider with one zoom and one pan for both sides. Keep leaves the result. Reveal opens the folder. Discard deletes the result and leaves the source. The view is painted with `ROOT_PLAIN` `#17171c` and the accent `#60a5fa`.

`--enlarge --path IMAGE` opens that window. `I` opens the info panel in the same process.

## Checks

`tests/test_enlarge.py` covers the capabilities object (including `gpu.status` `none` with `no_nvidia`), the day cache, the CLI progress stream, retryable `model_missing` (exit 7), the published CLI flags, cancel (exit 130), `--dry-run` without writing a file, the disabled action and Install Enlarge button, collision names, the split colours, zoom around the cursor, and Keep / Discard.

## Still open

- The reference laptop cold run is still the owner's `bench/Run-M0.ps1` pass.
- The real Enlarge server is not in this test. The mock scales with nearest-neighbour pixels. It does not download weights. A file whose name contains `missing-model` is a mock hook for `model_missing`; the product uses the model registry.
- Flatpak is not planned, so there is no `flatpak run` probe.
- The Windows pipe ACL is Qt `UserAccessOption` (current user), set before `listen`.
- `I` opens the info panel. `--enlarge --path` opens Enlarge. Both run in `voxprint-lucent-tools`.

# M3 Enlarge hand-off

Lucent's Enlarge client lives in the tools process. The C++ viewer does not talk to Enlarge, and `--benchmark` does not start the tools process. The 250 ms first-pixel guard is unchanged.

The product Enlarge server is not available yet. CI runs the client against `python -m voxprint_lucent.enlarge_mock`, which speaks protocol 1. The agreed contract is [IPC-ENLARGE.md](IPC-ENLARGE.md). How Lucent finds Enlarge is [APP-DISCOVERY.md](APP-DISCOVERY.md). Lucent keeps its own copy of that lookup in `voxprint_lucent/discovery.py` until a shared `voxprint-common` package is approved.

## What works

- Discovery reads `LUCENT_ENLARGE_EXE` (a test hook), then the Linux desktop file or the Windows `HKCU\Software\Voxprint\Enlarge` key (including `InstallPath`, `Version`, and `IpcName`), then App Paths, then `voxprint-enlarge` on `PATH`. The executable has to exist. Flatpak is not probed.
- `--capabilities --json` is cached for a day and refreshed when the registered `Version` changes. `gpu.status` `ok` enables the actions. `warn` leaves them enabled and puts the reason (`below_rtx_40` on the mock) on the tooltip. `none` hides them and shows `no_nvidia` or `driver_too_old`. The probe itself still exits 0 when there is no GPU. `--serve` refuses in that case.
- Quick enlarge and Open in Enlarge send `hello` and `enlarge.request` on the local socket. The client starts `voxprint-enlarge --serve --hidden` when nothing is listening, waits up to 3 seconds, and falls back to `--json-progress` if the socket never comes up.
- Hello uses client name `lucent` and requires protocol 1 in the server's `protocols` list. Requests send an absolute path, `quality`, optional `model`, and JSON `null` when `output` or `output_dir` is omitted.
- Progress, `done`, and `error` (including retryable `model_missing`) are handled. Cancel sends the `cancel` message. A CLI run is stopped by terminating the process. `io_error` and `internal` are not retryable.
- The default result is `<name>.enlarged-<scale>x.<ext>` beside the source. JPEG uses `.jpg`. A collision starts at `-1` (`shot.enlarged-2x-1.avif`, or `out-1.avif` for an explicit path). PNG is rejected. The source is never overwritten.
- The compare view is a split slider with one zoom and one pan for both sides. Keep leaves the result. Reveal opens the folder. Discard deletes the result and leaves the source. The view is painted with `ROOT_PLAIN` `#17171c` and the accent `#60a5fa`.

`--enlarge --path IMAGE` opens that window. `I` opens the info panel in the same process.

## Checks

`tests/test_enlarge.py` covers the capabilities object (including `gpu.status` `none` with `no_nvidia`), the day cache, the CLI progress stream, retryable `model_missing`, the socket hello / request / done path, cancel, the CLI fallback, collision names, the split colours, zoom around the cursor, and Keep / Discard.

## Still open

- The reference laptop cold run is still the owner's `bench/Run-M0.ps1` pass.
- The real Enlarge server is not in this test. The mock scales with nearest-neighbour pixels. It does not download weights. A file whose name contains `missing-model` is a mock hook for `model_missing`; the product uses the model registry.
- Flatpak is not planned, so there is no `flatpak run` probe.
- The Windows pipe ACL is Qt `UserAccessOption` (current user), set before `listen`.
- The tools stub and the M2 info panel are different edits of `tools_host.py`. Whichever milestone merges second has to fold the other window in.

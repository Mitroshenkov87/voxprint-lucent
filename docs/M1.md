# M1 core viewer

The interactive viewer is `Browser` in the C++ executable. `--benchmark` still constructs only `Viewer`: one decode, one raster paint, `FIRST_PIXEL`, then quit. That path does not build the folder list, the look-ahead cache, or the RHI widget.

## What works

- Folder order is natural on Linux and `StrCmpLogicalW` (Explorer order) on Windows. Left and Right move through the folder, wrapping at the ends.
- Look-ahead keeps two images ahead and two behind, on a pool of two decode threads, with a 256 MB cap. A cached neighbor is shown without decoding again.
- Zoom: fit, fill, 1:1, fit width, fit height, and cursor-anchored wheel zoom. Drag pans, and the pan eases out after release.
- F11 fullscreen, frameless, window-fit, and a 3 second slideshow.
- Multi-frame files (GIF, APNG, animated WebP, multi-page TIFF, and animated JPEG XL when the plugin reports frames) play on their own delay. Period and comma step frames.
- JPEG still uses DCT scaling via `setScaledSize`. JPEG XL requests the same reduced size when the plugin advertises `ScaledSize`. Zooming past 1:1 starts a full-resolution decode. AVIF and JPEG XL stay multi-threaded inside the KImageFormats plugins.
- EXIF orientation is applied by `QImageReader::setAutoTransform`. Embedded ICC profiles are converted to sRGB through Qt. Floating-point HDR frames are converted to 8-bit after that.
- HEIF, RAW, and EXR/HDR open when a system plugin is installed. If it is missing, the window says so. libde265 and x265 are not bundled.
- English is the default. Ctrl+L cycles Russian and German. Ctrl+K remaps keys; the overrides are stored in `QSettings`.
- `I` starts `voxprint-lucent-tools` for the file that is open. That process is not started with the image.
- After the first raster paint, Qt 6.7+ builds a `QRhiWidget` (D3D12 on Windows, Vulkan on Linux) for later zoom and pan. `LUCENT_RHI=0` keeps the `QPainter` view. If the device fails, the widget hides and painting stays on the CPU.

## Checks

`cpp/tests/m1_logic.cpp` covers natural order, fit placement, cursor-anchored zoom, and pan. The Ubuntu CI smoke compiles that test, then runs `--benchmark` twice on a tiny JPEG. The second run must print `FIRST_PIXEL` and an in-process `first_image_presented_ms`. The job records that time and does not fail when a shared runner is slow. That image has no preview, so the sample is the full decode, and it is warm. For v0.1.x the cold first pixel is 450 ms and the warm JPEG gate is 250 ms. The laptop scores those with `bench/Run-M0.ps1` and `vm_test`. The 350 ms warm budget for a 12 megapixel AVIF or JPEG XL stays on `bench/Run-M0.ps1`.

## Still open

- The reference laptop cold run is still the owner's `bench/Run-M0.ps1` pass. CI does not reboot.
- 12 MP AVIF and JPEG XL stay decode-bound. Their warm full-resolution budget is 350 ms. The bench files carry no embedded preview, and libavif 1.0.4 leaves thumbnail-item decode unimplemented, so the first pixel on those files is the full decode. Numbers are in [CI.md](CI.md).
- Colour stops at sRGB. A monitor profile through a separate lcms2 link is not wired.
- RAW, EXR, and HEIF are only as good as the codecs installed on the machine. The CI smoke image is a JPEG. The Windows zip carries the AVIF and JPEG XL plugins from M0.
- The tools process hosts the info panel ([M2.md](M2.md)). Enlarge is the `--enlarge` path in [M3.md](M3.md).
- There is no CLI in this milestone.
